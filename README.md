# Backend Lab: Python / FastAPI

Персональная система перехода из frontend в backend/fullstack через практику.
Профиль: 6 лет frontend, знакомый Python, команда использует FastAPI.
Цель: самостоятельно проектировать, тестировать, развёртывать и диагностировать backend-сервисы. Прохождение программы само по себе не присваивает уровень senior.

## Начать

Открой этот репозиторий в Codex и напиши:

> Используй $backend-mentor. Начнём диагностику D00. Задавай вопросы по одному, не показывай ответы заранее.

Skill находится в `.agents/skills/backend-mentor/`. Если клиент ещё не обнаружил новый skill, начни новую сессию. Можно явно попросить прочитать `.agents/skills/backend-mentor/SKILL.md` и работать по этим инструкциям.

## Как заниматься

1. Выбери один тикет. Сначала сформулируй подход и критерии проверки.
2. Пиши код в `practice/`, запускай его и сохраняй результаты проверки.
3. Попроси ревью: «Проверь B01, сначала находки и вопросы, без исправления за меня».
4. После исправлений объясни компромиссы и реши небольшую новую задачу без помощи.
5. Наставник обновит прогресс и краткую запись сессии на основании наблюдаемого результата.

Полезные запросы:

- «Продолжим обучение» — выбрать следующий шаг по прогрессу.
- «Застрял, вот моя попытка…» — получить одну подсказку подходящего уровня.
- «Проведи тренировку диагностики» — разобрать воспроизводимый сбой.
- «Повтори слабые темы» — самостоятельные вопросы в новом контексте.
- «Покажи полный разбор» — получить решение; оно не считается самостоятельным прохождением.
- «Режим реализации: сделай …» — явно поручить агенту работу вместо учебного упражнения.

Время на неделю пока не задано. Рабочий ориентир — 8 часов, без обещаний фиксированной даты достижения senior. Сроки корректируются по фактическим занятиям.

## Стек

Python, FastAPI, Pydantic 2, PostgreSQL, SQLAlchemy 2, Alembic, pytest, HTTPX, Docker Compose. Версии фиксируем при создании первого приложения после проверки совместимости. Redis, очередь, CI и наблюдаемость вводим под задачи. Детали стека команды уточняем по мере необходимости.

Приложение и зависимости ещё не созданы: первый запуск — часть B01. Платные API, внешние аккаунты и Obsidian для старта не нужны.

## Продолжение с другого устройства

GitHub, ветка `master`, хранит учебные контрольные точки. Наставнику разрешено коммитить и отправлять каждое содержательное обновление без повторного подтверждения. Успешная отправка подтверждается в чате; ошибка отправки означает, что свежая запись пока только локальная.

В новом чате открой этот репозиторий и напиши: «Используй $backend-mentor, обнови данные из GitHub и продолжим с сохранённого шага». Перед сменой чата можно попросить: «Сохрани контрольную точку». Устройство или чат должны иметь доступ к репозиторию; одной переписки без файлов недостаточно для восстановления прогресса.
