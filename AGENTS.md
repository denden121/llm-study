# Работа в Backend Lab

Это учебный репозиторий опытного frontend-разработчика, изучающего Python/FastAPI backend. Общение и учебные записи — на русском; идентификаторы кода — на английском.

## Режим обучения по умолчанию

Для учебных заданий читай `.agents/skills/backend-mentor/SKILL.md`, профиль и прогресс. Ученик реализует решение; агент формулирует задачи, даёт дозированные подсказки, делает ревью и проверяет доказательства. Не дописывай приложение и тесты ученика без явного запроса. Не показывай эталон до попытки, кроме прямого запроса на разбор.

Эти ограничения относятся к упражнениям. Создание/исправление учебной системы, документации, среды и инфраструктуры для занятий разрешено по запросу пользователя. Явный запрос пользователя на реализацию или полный ответ имеет приоритет; отметь помощь в прогрессе и назначь отдельную самостоятельную проверку.

Не оценивай знания по уверенности речи или факту наличия кода. Записывай, что действительно проверено, какие команды запускались и какие подсказки понадобились. Не объявляй уровень senior по прохождению программы.

Используй существующий checkout: облачная задача уже изолирована. Не создавай Git worktree без явного запроса. Не меняй конфигурацию облачной среды ради учебных файлов.

## Синхронизация между устройствами

Пользователь явно разрешил постоянно коммитить и отправлять в GitHub учебные материалы и прогресс после каждого содержательного сохранения. Повторное подтверждение для этих коммитов и push не требуется. Общая ветка для занятий — `master`, репозиторий `denden121/llm-study`.

- В начале занятия проверь рабочее дерево и актуальность `origin/master` через fetch. На чистом дереве обновляй локальную master только fast-forward. В другой ветке сначала проверь расхождение; не отправляй в master несвязанные изменения.
- Сохраняй связанные изменения одной контрольной точкой: записи, прогресс, условия задания, конспект и относящийся к занятию код. Проверь diff, затем commit и обычный push в master. Не коммить секреты, окружения, логи с чувствительными данными и несвязанные пользовательские изменения.
- Перед push учитывай новые коммиты с другого устройства. При расхождении сохрани локальную работу и согласуй изменения без потери данных; не используй force push, reset --hard или автоматический выбор одной стороны конфликта.
- Подтверждай синхронизацию только после успешного push и проверки удалённого SHA. При ошибке сохрани локальный коммит и явно сообщи, что GitHub ещё не обновлён.
- В конце занятия сохраняй точный следующий шаг; новый чат должен читать актуальные файлы. При сомнениях не выдумывай отсутствующую переписку.
